概要

研究者は、GitHub.comおよびGitHub Enterprise Serverに影響する重大な脆弱性CVE-2026-3854を公開した。この欠陥はCVSS 8.7のコマンドインジェクションであり、攻撃者がリポジトリへのpush権限を持つ場合、単一のgit push操作でリモートコード実行（RCE）を達成できる可能性がある。攻撃成立には認証済みアカウントが必要だが、内部開発環境やCI/CD連携を介して権限を得た攻撃者が横展開に利用するリスクがある。GitHub.com側では修正済みとされるが、オンプレミス版（Enterprise Server）の更新状況は組織ごとに異なり、未更新環境では影響が継続する。現時点で実際の悪用報告はないが、PoCの出回り次第で内部リポジトリを狙う攻撃が増加する懸念がある。

Git push

ローカル変更をリモートリポジトリに送信する操作。通常は認証済みユーザに限定されるが、CI/CD連携経由で自動実行される場合もある。

GitHub Enterprise Server

オンプレミス運用が可能なGitHub版。GitHub.comと異なり、パッチ適用は管理者責任であり、更新遅延がリスク要因となる。

RCE（Remote Code Execution）

攻撃者がリモートから任意コードを実行できる状態。単なる情報漏えいではなく、完全なシステム支配につながる。

深掘り解説

ソースコード管理系サービスにおける権限境界の脆弱性評価

GitHubやGitLabなどのソースコード管理系サービスは、開発者権限を前提に多くの自動処理を行うため、認証済みユーザによる攻撃が成立しやすい構造を持つ。今回のCVE-2026-3854のように、push操作がサーバ側でコマンド実行に繋がる場合、内部ユーザや侵害済みCIトークンを経由した攻撃が現実的となる。実務では「外部からの侵入」だけでなく、「開発環境内の信頼境界」を再評価することが重要である。例として、リポジトリごとにデプロイキーやトークンを分離し、pushイベントをトリガーとする自動ジョブの実行権限を最小化することで、RCE経路を限定できる。また、GitHub Enterprise Serverのようなオンプレ環境では、GitHub.comと異なり自動更新が行われないため、脆弱性情報の入手とパッチ適用を運用プロセスに組み込む必要がある。
