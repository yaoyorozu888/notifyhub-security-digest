Microsoft Details Cookie-Controlled PHP Web Shells Persisting via Cron on Linux Servers

攻撃は既に侵入済みサーバを前提とするが、Cookie制御による検知回避とcron永続化により封じ込めが難しい。Microsoftによる一次分析報告で信頼性が高く、実運用上の対応優先度も高いためHighとした。

概要

Microsoft Defender Security Research Teamは、Linuxサーバ上で稼働するPHPベースのWebシェルが、HTTPクッキーを利用してコマンド制御を行う新たな手法を確認したと報告した。従来のURLパラメータやPOSTボディを使う方式と異なり、攻撃者が送信する特定のクッキー値をトリガーとしてリモートコード実行を行う。この仕組みにより、通常のWebアクセスログやWAFルールでは検知が困難となる。また、攻撃者はLinuxのcronジョブを用いてWebシェルを永続化し、再起動後も制御を維持することが確認されている。現時点で特定のキャンペーン名や侵入経路の詳細は明らかでないが、既存のPHPアプリケーションの脆弱性悪用後に設置されるケースが多いとみられる。

判断ポイント

  • 攻撃成立には既にWebサーバへの侵入が前提であり、初期侵入経路の特定が防御の鍵となる。
  • クッキー経由の制御は通常のリクエスト検査では可視化されにくく、HTTPヘッダレベルでの監視が必要。
  • cronによる永続化はシステム権限で動作するため、検知遅延時の横展開リスクが高い。

対応アクション（今すぐ・継続）

  • [今すぐ] Webサーバ上のcron設定・ユーザcrontabを確認し、不審なPHP呼び出しや外部通信を削除。
  • [今すぐ] WAFやIDSのルールを見直し、Cookieヘッダ内の異常値を検知対象に追加。
  • [継続] PHPアプリケーションの更新・脆弱性管理を徹底し、侵入後のWebシェル設置を防ぐ基盤整備を行う。
