Critical Unbound DNSSEC Validator Flaw Could Allow RCE via a Malicious DNS Zone

Impact判定理由

DNSSEC 検証処理のヒープオーバーフローで、悪意あるゾーンと問い合わせ誘導だけで RCE に至るため、技術的深刻度は極めて高い。再帰 DNS リゾルバは組織内の通信基盤に直結し、侵害時の影響は広範な名前解決停止や横展開の足がかりまで及ぶ。情報源が二次報道の The Hacker News である点は慎重に見る必要があるが、同日修正版と CVE 公開が示されており、一次情報に基づく緊急性は高い。

概要

Unbound の DNSSEC 検証処理に、1.26.1 より前の版へ影響する ヒープオーバーフローが見つかった。悪意あるゾーンを用意した攻撃者が、脆弱な再帰 DNS リゾルバへ問い合わせを誘導すると、リモートコード実行に至る可能性がある。影響は名前解決基盤そのものに及ぶため、単一端末の障害ではなく、社内外の広い通信失敗や認証・更新処理への波及が起こり得る。公開情報では修正版 1.26.1 が同日に出ており、CVE-2026-81642 として追跡されているが、実際に悪用コードが広く出回っているか、既存設定でどこまで到達可能かは未確認である。

📌 キーワード解説

DNSSEC

DNS応答の改ざん検知機構。暗号化とは別で、検証失敗は通信不能よりも偽装検知に効く。

ヒープオーバーフロー

確保領域を越えて書き込む不具合。単なるクラッシュだけでなく、任意コード実行へつながりやすい。

再帰DNSリゾルバ

名前解決を代理する基盤。権威DNSより攻撃面が広く、社内全体の通信影響に直結しやすい。

深掘り解説

名前解決基盤の脆弱性は、単一サーバ障害として扱わない

DNS リゾルバの脆弱性は、攻撃対象が 1 台でも影響範囲が組織全体へ広がりやすい。理由は、端末や業務アプリが共通の名前解決に依存しているため、侵害が起きると多くの通信の起点を奪われるから。たとえば社内の Unbound が侵害されると、利用者は Web 閲覧だけでなく、SaaS 認証、ソフトウェア更新、内部 API 呼び出しまで不安定になる。さらに DNSSEC 検証に触れる欠陥は、単なる応答改ざんではなく、検証ロジックのメモリ破壊として RCE へ接続する点が重い。CSIRT では「DNS は止めると困る基盤」だからこそ、障害対応ではなく侵入前提で見る必要がある。具体的には、外部到達性、利用版数、再帰問い合わせを受ける経路、そして検証機能の有効化状況を先に切り分けると、封じ込め判断がぶれにくくなる。
