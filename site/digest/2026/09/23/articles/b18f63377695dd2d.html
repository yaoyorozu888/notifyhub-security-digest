概要

Microsoft が当初はなりすましとして扱った SharePoint Server の欠陥が、実際には認証済みのリモートコード実行につながると報じられた。対象は SharePoint Server 2016、2019、Subscription Edition で、CVE-2026-65660 として整理されている。攻撃が成立すると、既存の有効アカウントを使ってサーバー上で任意コードを動かせるため、単なる表示改ざんよりはるかに重い。影響は単一サイトの改ざんにとどまらず、SharePoint 上の情報流出、横展開、資格情報の追加悪用へ広がる余地がある。記事要約だけでは、前提となる権限、公開条件、実際の悪用有無、修正の適用状況が読み取れないため、そこは未確認事項として残る。

深掘り解説

認証済み脆弱性は「入口の狭さ」で軽く見ない

認証済みでしか使えない欠陥は、一見すると未認証RCEより優先度が下がるように見える。しかし実運用では、外部委託先、退職済みアカウントの残存、共有ID、弱い多要素認証回避などで「認証済み」の前提が崩れやすい。さらに SharePoint のような業務基盤は、文書保管だけでなく検索、権限継承、連携アプリ、ワークフローを抱えていることが多く、1台の侵害が複数部門へ波及しやすい。 具体例として、社内ポータルに入れる一般ユーザー権限しかなくても、Web パーツの改ざんやサーバー側コード実行が可能なら、攻撃者はファイル窃取の足場を作れる。そこから管理者のセッション情報、接続先の資格情報、同期先の共有フォルダをたどって横展開する流れが現実的になる。したがって、評価の起点は「未認証かどうか」だけではなく、「その権限で何が到達可能か」「監査ログに何が残るか」「封じ込め時にどの業務が止まるか」まで含めて見る必要がある。SharePoint では、パッチ適用に加えて、利用者権限の棚卸し、外部公開面の確認、異常なファイル生成やプロセス起動の監視を同時に進めると判断がぶれにくい。
