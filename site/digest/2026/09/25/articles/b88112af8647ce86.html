概要

Proofpoint が、TeamFiltration を用いた活動として UNK_CondorFiltration を公表した。対象は 28 の Microsoft 365 テナントで、5,700 件超のアカウントが狙われ、少なくとも 7 件の侵害が確認された。主な標的はチリの小売・金融機関とされ、攻撃の起点として 1,487 個の AWS EC2 送信元 IP が観測されている。既定パスワード の残存や弱い認証運用が前提なら、同種の攻撃は短時間で複数アカウントへ広がりやすい。

攻撃手口の要点は、単発の脆弱性悪用ではなく、認証情報の使い回しや初期設定のまま放置されたアカウントを大量に試す点にある。成功するとメール、ファイル、会議、認証基盤の横展開に波及し、侵害範囲はテナント内の他ユーザーや連携先へ伸びるおそれがある。現時点で、侵入後の持続化や二次被害の全容、対象組織側の具体的な設定不備は明示されていない。したがって、被害の広がり方は大きい一方で、実際の成功条件はテナントごとの差が大きいと見る必要がある。

この種の活動では、MFA 未適用、レガシー認証、初回ログイン後のパスワード変更漏れ、休眠アカウント放置が特に危険となる。検知では、短時間の大量失敗、地理的に不自然な試行、AWS 由来の分散した送信元、同一ユーザーへの連続試行を優先して確認する。封じ込めは、影響アカウントの無効化、パスワード再設定、トークン失効、条件付きアクセスの強化が中心になる。メディア報道ベースではあるが、具体的な侵害件数と広範な試行規模が示されており、注意喚起の優先度は下げにくい。

TeamFiltration

パスワードだけでは通さない仕組み。既定パスワードや使い回し対策と混同せず、認証突破後の被害抑止に効く。

レガシー認証

古い認証方式の総称。条件付きアクセスや強固な多要素認証を迂回されやすく、残存確認が重要になる。

今回のような攻撃では、1つ1つの失敗は目立たなくても、分散した送信元から多数のアカウントへ薄く広く試されることが本質になる。防御側が回数だけを見ていると、しきい値に達しないまま成功されやすい。 実務では、同一 IP の失敗回数よりも、短時間に複数ユーザーへ広がる試行、同じ ASN やクラウド基盤からの連続アクセス、地理的に不自然なパターンをまとめて見る必要がある。たとえば、AWS EC2 由来の多数 IP から、チリの拠点だけでなく別地域の社員アカウントにも断続的に試行が来ている場合、単純なブルートフォースではなく、認証突破を前提にした広域キャンペーンを疑うべきになる。 対処も「落ちたアカウントだけ閉じる」では足りない。休眠アカウントの無効化、初期パスワードの強制変更、MFA の必須化、レガシー認証の遮断、さらに成功したログイン後のトークン失効まで一体で進める必要がある。攻撃者は一度入れたアカウントを踏み台にし、メール転送や権限確認を通じて次の被害を狙うため、入口だけ塞いでも終わらない。
