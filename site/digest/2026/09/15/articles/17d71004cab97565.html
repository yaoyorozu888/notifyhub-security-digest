概要

Telegram Desktop のエクスポート機能に関する不具合が報告され、HTML 形式で保存したチャットに、見えない JavaScript を混入できたとされる。ユーザーがそのエクスポートファイルを Web ブラウザで開いた時点でスクリプトが動き、ファイル内のメッセージを外部へ送信できる可能性がある。悪用の起点は ボット経由の通常メッセージに見せかけた誘導で、受信者がエクスポート後に閲覧する運用を狙う形になる。影響はエクスポートされた履歴の内容に限られる見込みだが、会話の機微情報や添付先への足がかりが含まれると被害は大きくなる。現時点では、対象バージョン、再現条件、実際の流出規模は未確認となっている。

📌 キーワード解説

HTML エクスポート

会話を静的なWebページとして保存する形式。アプリ内表示と違い、ブラウザ解釈を前提にするため、混入コードの影響を受けやすい。

JavaScript

ブラウザ上で動くスクリプト。単なる表示文字列と違い、開いた瞬間に外部送信や画面操作へつながる点が危険になる。

ボット

自動応答主体の送信元。人手の送信より監視をすり抜けやすく、通常メッセージに紛れた誘導で悪用されやすい。

深掘り解説

エクスポートは「保存」ではなく「再実行される表示物」になる

静的な保存形式でも、閲覧時にブラウザが解釈する作りなら、実質的には小さなWebページとして扱う必要がある。ここで重要なのは「元のアプリで安全に見えた内容」が、そのまま安全とは限らない点になる。 今回の論点は、チャット本文そのものよりも、エクスポート後の閲覧経路にある。たとえば、社内で「証跡として会話をHTMLで保管し、あとでブラウザで確認する」運用があるとする。この場合、保管対象は証拠であっても、閲覧時にはスクリプトや外部参照を実行しうるため、端末側の情報や同一ファイル内の別メッセージを持ち出される余地が生まれる。 実務では、保存形式を選ぶ段階で脅威モデルを分ける必要がある。内容確認だけならPDFやテキストのように実行要素が少ない形式を優先し、HTMLを使うなら、隔離端末・オフライン・スクリプト無効化などの前提を置く。逆に、通常ブラウザで開く前提のまま保管物を扱うと、証跡ファイルが攻撃面に変わる。CSIRTとしては、ファイルの中身だけでなく「誰が、どの端末で、どのビューアで開くか」まで管理対象に入れる発想が重要になる。
