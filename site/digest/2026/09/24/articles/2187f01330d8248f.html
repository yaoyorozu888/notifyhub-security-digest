概要

Next.js の ImageResponse に、攻撃者が細工した SVG 入力 を与えることで サーバ側でコード実行 につながる脆弱性が見つかった。影響を受けるのは、URL 由来の文字列など、外部入力をそのまま画像生成に渡している構成になりやすい。悪用できれば、SNS 向けのプレビュー画像生成という一見軽い機能が、アプリ実行権限の奪取口に変わる。被害は単一リクエストで終わらず、機密情報の窃取や横展開の足がかりに広がる可能性がある。未確認事項として、実際の悪用事例、影響を受けるバージョン範囲、パッチ適用後の互換性影響が残る。

この件は メディア報道 由来であり、一次情報の詳細確認は別途必要となる。とはいえ、入力を画像や SVG に変換する処理は、想定外の解析経路を踏みやすく、CSIRT ではアプリ層の脆弱性として扱うべき場面が多い。特に、公開 Web アプリでプレビュー生成を有効にしている場合は、利用頻度が低くても攻撃面として残りやすい。

ImageResponse

Next.js の画像生成機能。通常の表示処理と違い、入力が描画処理へ流れるため、サニタイズ不足がそのまま危険化しやすい。

SVG

ベクター画像形式。画像に見えても内部にスクリプトや外部参照の余地があり、単純な画像扱いと混同すると事故につながる。

サーバ側コード実行

攻撃者の入力でサーバ上の処理を動かされる状態。クライアント側の改ざんより影響が広く、認証情報の奪取に直結しやすい。

深掘り解説

画像生成機能は「表示」ではなく「実行面」として扱う

プレビュー画像や OG 画像の生成は、見た目の機能に見えても内部では文字列解析、画像レンダリング、外部参照の解釈が走ることがある。ここに攻撃者制御の入力が混ざると、単なる文字列表示ではなく、処理系に負荷や解釈の差を起こす入口になる。 実務上のポイントは、画像生成の前段で「何を外部入力として受けるか」を決め切ることにある。たとえば URL のクエリ文字列をそのままタイトルに使う実装では、表示崩れだけでなく、SVG の解釈やテンプレート展開の想定外経路が生まれる。そこで、許可する文字種を絞り、長さ制限を入れ、画像生成系には固定文言だけを渡す設計に寄せる。 具体例として、SNS 用カード画像を作る API が `?title=` の値を直接描画している場合を考える。ここで攻撃者が特殊な SVG 断片や巨大文字列を送り込むと、生成処理が例外終了するだけでなく、実装次第では内部オブジェクトの参照やテンプレート処理に波及する。したがって、CSIRT では『静的な画像出力だから安全』という前提を捨て、レンダラーや変換ライブラリも通常の入力処理と同じく監視対象に置く必要がある。
