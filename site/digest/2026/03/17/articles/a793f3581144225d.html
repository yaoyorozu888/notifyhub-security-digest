VU#624941: LibreChat RAG API contains a log-injection vulnerability

🗞️ CERT/CC 🕒 2026-03-17T00:30:40+09:00 🔗 原文を開く
Impact: High Vulnerability
原文リンク 日次トップ

Impact判定理由

認証済み攻撃者による監査ログ改ざんが可能で、事後対応やフォレンジックに影響。さらに二次処理系でXSS/RCE誘発の恐れ。CERT/CC公表により悪用現実性が高く、ベースMediumから+1補正。

🧾 要約（ChatGPT）

概要

CERT/CCは、LibreChat RAG API v0.7.0におけるログインジェクション脆弱性（VU#624941）を公表した。ユーザ入力がログ出力時に適切にサニタイズされず、CRLF文字を挿入することで認証済み攻撃者がログを改ざん・偽造できる。これにより、監査証跡の信頼性が損なわれ、不正行為の隠蔽や誤誘導が可能となる。また、改ざんログを不適切に処理するログ管理ツール経由でXSSやRCEなどの二次攻撃に発展する恐れがある。ベンダーへの連絡は不通で、修正版は未提供。CERT/CCは入力フィルタ導入やpgvector拡張の無効化、RAG出力の検証を推奨している。

現場の学び

  • 本件は認証後攻撃ながら、監査ログの改ざんにより事後調査を攪乱できる点が実務上のリスク。
  • RAGやLangChainなど生成AI基盤のAPI層でも、入力検証不備が伝統的脆弱性を再現することを示す。
  • ログインジェクションは単体では軽視されがちだが、二次処理系（SIEM・可視化ツール）への波及が実害を生む。

初動・継続対応の示唆

  • LibreChatや類似RAG APIを利用している場合、ログ出力箇所のCRLFエスケープ処理を即時確認。
  • 監査ログの完全性を担保するため、改ざん検知（ハッシュチェーン等）の導入を検討。
  • 生成AI系APIを含む新規サービスでは、ログ設計レビューを開発段階で組み込む運用体制を確立。

📌 キーワード解説

Log Injection（ログインジェクション）

ログ出力時に未検証入力を混入させ、ログ構造を改変する攻撃。SQL Injectionと異なり、監査証跡の信頼性を狙う。

CRLF（Carriage Return Line Feed）

改行制御文字。HTTPヘッダ分離やログ改ざんに悪用される。入力検証で除去・エスケープが必要。

RAG（Retrieval-Augmented Generation）

外部知識を検索し生成AIに補強する手法。生成精度向上の一方、入力経路が複雑化し攻撃面が拡大する。

pgvector

PostgreSQL拡張でベクトル検索を実現。AI検索用途に有用だが、不要時は無効化で攻撃面縮小が可能。
