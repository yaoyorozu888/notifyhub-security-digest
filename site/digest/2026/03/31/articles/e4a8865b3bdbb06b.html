LibreChat RAG API にログインジェクションの脆弱性

Impact: High Vulnerability

Impact判定理由

直接的なRCEではないが、監査ログ改ざんにより検知・調査を妨害できる点で運用上の影響が大きい。公的機関発信ではなくメディア報道のため補正は据え置き。

🧾 要約（ChatGPT）

概要

LibreChat の RAG API において、ログ出力処理にユーザ入力が不適切に挿入されるログインジェクション脆弱性が報告された。攻撃者は特定のリクエストを送信することで、ログの改ざんや偽装を行い、後続の調査・検知を妨害する可能性がある。この脆弱性自体は直接的なリモートコード実行を伴わないが、インシデント対応や監査ログの信頼性を損なう点で重大である。特にRAG APIが外部入力を扱う構成や、複数サービス間でログを集約している環境では、攻撃痕跡の隠蔽や誤検知誘発につながるリスクがある。現時点では悪用事例は未確認だが、PoCレベルの再現は容易とみられる。

判断ポイント

  • 攻撃成立にはAPI経由で任意入力をログに反映できる構成が必要であり、外部公開APIや共有ログ基盤を持つ環境で影響が大きい。
  • 直接的なシステム侵害ではなく、検知・監査の信頼性低下を狙う二次的攻撃要素として評価すべき。
  • ベンダー修正版の有無が不明なため、暫定的なログサニタイズや監査ロジックの補強が当面の対応となる。

対応アクション（今すぐ・継続）

  • [今すぐ] RAG API のログ出力箇所を確認し、ユーザ入力が直接出力されていないか静的解析・grepで点検する。
  • [今すぐ] ログのフォーマット改ざんを検知できるよう、ログ署名・改行制御などの防御策を適用する。
  • [継続] LibreChat の公式リポジトリやアドバイザリを監視し、修正版リリース時に速やかに適用できる体制を整える。

📌 キーワード解説

ログインジェクション (Log Injection)

ログ出力時にユーザ入力がそのまま挿入され、改行や制御文字でログ構造を改変される脆弱性。SQLインジェクションと異なり、主に監査妨害を目的とする。

RAG (Retrieval-Augmented Generation)

外部知識を検索して生成AI応答に組み込む手法。API経由で外部入力を扱うため、入力検証不備が攻撃面を広げやすい。

サニタイズ (Sanitize)

入力データから危険な文字や構文を除去・変換する処理。エスケープと混同されやすいが、目的は安全な形式への正規化である。

ログ署名 (Log Signing)

ログの改ざん検知を目的にハッシュや署名を付与する手法。改行挿入や追記攻撃に対して整合性を保証する。
