Open VSX Bug Let Malicious VS Code Extensions Bypass Pre-Publish Security Checks

🗞️ The Hacker News 🕒 2026-03-27T22:57:00+09:00 🔗 原文を開く
Impact: High Supply Chain
原文リンク 日次トップ

Impact判定理由

拡張公開プロセスの検証抜けにより悪意あるコードが公式レジストリに掲載され得た。開発環境汚染のリスクが高いが、修正済みで悪用報告なし。メディア情報源のため補正なし。

🧾 要約（ChatGPT）

概要

Open VSX Registry の 拡張機能公開前スキャン処理に存在した不具合が修正された。問題は、スキャン結果を判定するブール値の実装ミスにより、スキャナが実行されなかった場合でも「安全」と誤認され、悪意ある VS Code 拡張機能が審査を通過して公開される可能性があった点にある。これにより、利用者が信頼してインストールした拡張経由でコード実行や情報窃取が起こり得た。攻撃の成立には拡張の配布とユーザのインストールが必要で、リポジトリ側の修正は完了しているが、過去に公開済みの拡張の再検証は未確認である。現時点で実際の悪用事例は報告されていないが、サプライチェーン経路の脆弱性として警戒が必要である。

判断ポイント

  • 本件は サプライチェーン攻撃の一形態であり、拡張配布基盤の信頼性が一時的に損なわれた点が重要。
  • 影響範囲は Open VSX 経由で拡張を導入する環境に限定されるが、内部開発環境の汚染リスクがある。
  • 修正済みとはいえ、既存拡張の再審査や署名検証が未実施である可能性を考慮し、利用側での検証が必要。

対応アクション（今すぐ・継続）

  • [今すぐ] Open VSX 由来の拡張を利用している開発環境を棚卸しし、信頼済みソースのみを許可する設定を確認。
  • [今すぐ] 内部配布拡張を含む VS Code 拡張の署名・ハッシュ検証を実施し、不審な更新を確認。
  • [継続] 開発環境のサプライチェーン監査を定期化し、拡張ストアやCI/CD連携の信頼モデルを再評価。

📌 キーワード解説

Open VSX Registry

VS Code 互換エディタ向けの拡張公開レジストリ。Microsoft公式Marketplaceと異なり、OSS環境で利用される。信頼モデルが異なる点が重要。

Pre-publish scanning

拡張公開前に自動実行される安全性検査。署名や依存関係を確認する。実行失敗時の扱いが脆弱だと検知抜けが発生する。

Supply chain attack（サプライチェーン攻撃）

開発・配布経路を汚染して侵入する攻撃。単体脆弱性より検知が難しく、信頼の連鎖を悪用する点が特徴。

VS Code Extension

Visual Studio Code の機能拡張。ユーザ権限でコード実行可能なため、悪意ある拡張は情報窃取や横展開の起点になり得る。
