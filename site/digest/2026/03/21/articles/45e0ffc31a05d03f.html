Magento PolyShell Flaw Enables Unauthenticated Uploads, RCE and Account Takeover

Impact判定理由

認証不要で任意コード実行が可能なRCE脆弱性であり、攻撃成立条件が比較的緩い。現時点で悪用確認はないが、Magento環境のREST API露出率を考慮すると実運用上のリスクは高い。情報源はメディア（The Hacker News）で一次情報はSansec報告のため、過大補正はせずHighとした。

概要

Sansecは、MagentoのREST APIに存在する重大な脆弱性「PolyShell」を報告した。この欠陥は認証なしで任意ファイルをアップロードできる問題で、攻撃者は画像ファイルに偽装したコードを送信し、リモートコード実行（RCE）やアカウント乗っ取りを実現できる。報告時点では悪用の証拠はないが、攻撃手法が単純で自動化しやすいことから、今後の悪用拡大が懸念される。影響範囲は、REST APIを有効化しているMagento CommerceおよびOpen Source環境全般に及ぶ可能性がある。

現場の学び

  • 攻撃成立にはREST APIが外部公開されている構成が前提であり、管理者認証が不要な点が特に危険。API公開範囲の棚卸しが防御の第一歩となる。
  • 画像アップロード処理を悪用するため、コンテンツ検証やMIMEタイプ確認の欠如が攻撃成功率を高める。Webアプリ層での入力検証強化が有効。
  • 攻撃者視点では、Webサーバ上でのシェル設置→横展開（DBや管理者アカウント奪取）というROIの高い流れが成立する。

初動・継続対応の示唆

  • まずREST APIの公開状態とアクセス制御を確認。不要なAPIは即時無効化し、外部からのPOSTリクエストを制限する。
  • Webサーバのアップロードディレクトリに対し、実行権限の除去やファイル拡張子制御を適用することで、RCEリスクを軽減。
  • 攻撃検知の観点では、/rest/配下への異常なPOSTや画像拡張子以外のアップロード試行をログ監視対象に追加する。

📌 キーワード解説

RCE（Remote Code Execution）

攻撃者が遠隔から任意コードを実行できる脆弱性。情報漏えいよりも深刻で、システム乗っ取りに直結する。

REST API

HTTP経由で操作可能なAPI。利便性が高いが、認証や公開設定を誤ると攻撃面が拡大する。

ファイルアップロード脆弱性

不正なファイルをサーバに送信できる欠陥。入力検証不足が原因で、RCEや情報漏えいに発展する。

MIMEタイプ検証

アップロードファイルの実際の形式を確認する手法。拡張子検査のみよりも信頼性が高い。
