概要

GitHub Actionsの利用実態を調査した結果、開発者の約半数がセキュリティ対策を十分に理解・実施していないことが判明した。特に「自分のリポジトリでは外部コントリビューションを受けないから安全」と誤解しているケースが多く、依存するワークフローや再利用アクションの信頼性を軽視する傾向が見られた。攻撃者は、人気のあるアクションや依存パッケージを汚染することで、CI/CD環境を踏み台に機密情報を窃取する手法を取るため、間接的なリスクが高い。調査では、トークン権限の過剰付与や、未固定のアクション参照（ブランチ指定など）も多く確認されている。

現場の学び

  • 「自組織で開発していないから関係ない」という認識は危険。GitHub Actionsは依存やフォーク経由で影響を受ける。
  • ワークフローのYAML定義はコードとして監査対象にすべき。権限設定や外部呼び出しをレビューする体制が必要。
  • Actionsのセキュリティ設定は開発チーム任せにせず、CSIRTがCI/CD基盤全体のリスク管理に関与する必要がある。

初動・継続対応の示唆

  • GitHubリポジトリでpermissions設定やGITHUB_TOKENのスコープを確認し、最小権限化を徹底する。
  • 再利用アクションは@shaで固定し、不審な更新や新規依存の追加を検知する仕組みを導入する。
  • CI/CD環境の監査ログを定期確認し、外部アクション呼び出しやSecretsアクセスの異常を検出できるルールを整備する。

📌 キーワード解説

GitHub Actions

GitHubのCI/CD機能。コードビルドやデプロイを自動化する。外部アクション利用時は依存リスクが高く、署名や固定参照で制御すべき。

GITHUB_TOKEN

GitHub Actions実行時に自動発行される認証トークン。権限過大だとリポジトリ改ざんや秘密情報取得の踏み台になる。

permissions設定

Actions内でのトークン権限を制御する設定。最小権限原則を適用しないと、意図せぬ書き込みや漏洩の原因となる。

再利用アクション

他者が公開するワークフロー部品。利便性が高いが、改ざんや悪意ある更新のリスクがあり、固定参照と署名確認が重要。
