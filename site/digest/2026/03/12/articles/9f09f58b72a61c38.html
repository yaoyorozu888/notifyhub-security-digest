概要

自動化ワークフロー基盤 n8n において、CVE-2025-68613（Improper Control of Dynamically-Managed Code Resources）がCISAのKnown Exploited Vulnerabilities（KEV）に追加された。これは、動的に管理されるコードリソースの制御不備により、攻撃者が任意コードを実行できる可能性がある脆弱性である。n8nはAPI連携や自動処理を担う中間層として利用されることが多く、認証情報やトークンを扱うため、侵害時の被害は横展開・情報漏えいに直結しやすい。CISAがKEVに登録したことは、実際の悪用が確認済みであることを意味し、迅速な対応が求められる。

現場の学び

  • n8nはDockerやクラウド上での常時稼働が多く、外部公開設定やAPI認証の緩さが攻撃面を拡大させる。
  • 「動的コード管理の制御不備」は、プラグインやスクリプト実行機構を持つ製品全般に波及しうる設計上のリスクを示す。
  • KEV掲載は「現実に攻撃が発生している」シグナルであり、PoC出回りやボット化リスクを前提に優先順位を上げるべき。

初動・継続対応の示唆

  • まず、n8nのバージョン確認と更新を最優先。コンテナ再ビルドや依存ライブラリ更新を含めて実施する。
  • 外部公開しているn8nインスタンスがある場合、アクセス制御・認証強化・不要ポート閉鎖を即時検討。
  • 侵入後の横展開を想定し、n8nで扱う認証情報（APIキー・OAuthトークンなど）の再発行を含む封じ込め計画を準備する。

KEV (Known Exploited Vulnerabilities)

CISAが実際に悪用が確認された脆弱性を公表するリスト。理論上の脆弱性情報とは異なり、攻撃活動の現実性を示す。

Improper Control of Dynamically-Managed Code Resources

動的にロード・実行されるコードの制御が不十分な設計不備。入力検証不備や権限境界の欠如と混同しやすい。

n8n

横展開 (Lateral Movement)
