Malicious npm Packages Harvest Crypto Keys, CI Secrets, and API Tokens

Impact判定理由

npm公式リポジトリに悪意あるパッケージが公開され、認証情報や暗号鍵の窃取を行う。開発環境・CI環境に波及する恐れがあり、実害リスクは高い。情報源はメディアだが、供給元がSocket社の一次分析で信頼性が高いため据え置き評価。

🧾 要約（ChatGPT）

概要

研究者が、npmリポジトリ上で19種類以上の悪意あるパッケージを利用したサプライチェーン攻撃を確認した。攻撃は「SANDWORM_MODE」と名付けられ、過去のShai-Hulud系列の活動と類似している。これらのパッケージは、インストール時にスクリプトを実行し、暗号資産ウォレット鍵・CI環境のシークレット・APIトークンなどを窃取する。特にCI/CD環境でnpmを利用するプロジェクトが標的となりやすく、開発者の認証情報を経由してGitHubやクラウドへの横展開が懸念される。

現場の学び

  • npm install時の自動スクリプト実行は攻撃面を拡大する。CI/CD環境では依存関係の固定とオフラインキャッシュ利用が重要。
  • 攻撃者は「人気ライブラリ名の typo」や「トランジティブ依存」を悪用する。依存チェーンの監査を自動化し、信頼できるスコープのみ許可すべき。
  • 盗まれたシークレットは暗号資産だけでなく、クラウドAPI・CIトークンを通じて組織内部資産への侵入に転用される可能性がある。

初動・継続対応の示唆

  • npmリポジトリの利用ログを確認し、該当パッケージ名の導入有無をスキャン。CI/CD環境の環境変数・シークレットの漏えいを確認する。
  • 依存関係の更新プロセスを見直し、lockファイルの署名検証やパッケージ署名機能（npm provenance）を活用する。
  • 開発環境でのネットワーク通信監視を強化し、npm install時の外部通信先をホワイトリスト化する。

📌 キーワード解説

Supply Chain Attack（サプライチェーン攻撃）

開発・配布経路を狙い、信頼済みソフトに悪意あるコードを混入させる攻撃。ゼロデイとは異なり、正規経路を悪用する点が特徴。

npm

JavaScriptのパッケージ管理システム。依存関係の自動解決が利便性だが、外部コード実行リスクが高い。

CI/CD

継続的インテグレーション／デリバリー環境。自動化の利点があるが、シークレット管理の不備が攻撃経路となる。

Typosquatting（タイポスクワッティング）

人気パッケージ名の綴り違いを悪用し、誤ってインストールさせる手口。依存監査で検出可能。
