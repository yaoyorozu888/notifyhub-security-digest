深掘り解説

CI/CD 基盤は『実行環境』であって『安全な内部資産』ではない

GitHub Actions のような CI/CD 基盤は、開発を高速化する一方で、外部からの入力をそのまま実行できる仕組みを抱える。ここを攻撃者に奪われると、単なるコード改ざんに留まらず、外向きスキャンや侵入試行の送信元として使われる。重要なのは、リポジトリの所有者が正規であっても、ランナー上で動く処理は常に信頼できるとは限らないと捉えることにある。 具体例を挙げると、プルリクエスト時に外部入力を参照するワークフロー、自己ホスト型ランナーに残った長期トークン、公開リポジトリでの秘密情報の参照などが重なると、攻撃者はそこを中継点にできる。結果として、外部から見れば正規の GitHub 関連通信に見えやすく、遮断や検知が遅れやすい。 実務では、ワークフローの権限最小化、秘密情報の分離、自己ホスト型ランナーの隔離、外向き通信先の制限を先に点検する価値が高い。今回は cPanel/WHM への攻撃が焦点だが、同じ構図はコンテナレジストリ、署名済み配布物、依存パッケージの配布経路でも起きる。攻撃者にとっての狙いは『脆弱な本体』ではなく『信頼された実行地点』にあるため、開発基盤の統制を本番資産と同列に扱う必要がある。
