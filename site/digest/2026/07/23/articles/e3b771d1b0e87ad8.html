深掘り解説

シリアライズ形式は「便利さ」と「危険な復元」を分けて考える

シリアライズは、オブジェクトを保存・転送しやすくする仕組みだが、復元時に何を実行できるかで安全性が大きく変わる。特に Python の Pickle は、単純なデータ表現ではなく、復元過程で任意の処理を起こし得るため、外部入力に向ける設計と相性が悪い。実務では「内部だけで使うつもりだった」経路が、後から API 化やバッチ連携で外部到達可能になることが多く、その時点で危険度が跳ね上がる。具体例として、モデル重みや設定ファイルを Pickle で受け取るサービスが、開発時は閉域でも、本番移行後にアップロード機能やジョブ投入機能を追加すると、攻撃者が細工したファイルを投げ込むだけで侵害に至る可能性がある。対策の要点は、まず信頼境界を越える入力に Pickle を使わないことに尽きる。次に、どうしても残すなら、到達元を強く制限し、ファイルの出所検証、権限分離、サンドボックス化、監査ログの取得を合わせて置く必要がある。運用では「その機能は誰が、どの経路で、何を復元するのか」を棚卸しし、データ形式の選定を機能要件ではなく攻撃面から見直すのが重要になる。
