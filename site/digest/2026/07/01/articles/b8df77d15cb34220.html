深掘り解説

ERP の脆弱性は「侵入可否」より「業務波及」で見る

ERP は、入口の脆弱性がそのまま業務影響に直結しやすい。たとえば Web 画面の不備に見えても、背後では発注、請求、支払、権限設定、外部連携が連動していることが多い。攻撃者は単にログインしたいのではなく、業務データの改ざんや不正送金、監査証跡の操作を狙う。したがって初動では「この CVE で何が壊れるか」だけでなく、「侵害後にどの業務が止まるか」「どの API やバッチが外部へつながっているか」を見る必要がある。具体例として、決済モジュールの権限不備があれば、請求先変更や支払先追加を起点に不正送金へつながる可能性がある。逆に、パッチ未適用の有無だけで安心せず、公開経路、VPN 経由、委託先アクセス、アプリ間連携の入口まで含めて点検することが重要になる。
