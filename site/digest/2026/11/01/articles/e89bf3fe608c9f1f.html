A Shared ChatGPT Link Could Run Attacker Code in Your Session and Read Private Chats

概要

セキュリティ企業Parameterの研究者は、細工されたChatGPT共有リンクを開いた利用者のログイン済みセッション内で攻撃者のコードが実行され、非公開の会話を読まれる問題を報告した。攻撃には、対象者がChatGPTにログインした状態でリンクを開くことが必要とされ、共有リンクを使った誘導が現実的な入口になり得る。漏えい対象は当該リンクで共有された会話に限らず、セッションからアクセスできる他の会話にも及ぶ可能性があるが、実際にどの範囲まで読み出せたかは公開情報から確認できない。研究者は10月18日にOpenAIの報奨金制度を通じて報告し、OpenAIは8日後に修正したうえで、深刻度を同社のP1と評価した。修正済みとの報告はあるものの、影響した利用条件や版、実悪用の有無、情報流出の発生状況は明らかでなく、リンクを受け取っただけの利用者と実際に開いた利用者を分けて確認する必要がある。

📌 キーワード解説

認証済みセッション内のコード実行

利用者がログイン済みの状態を攻撃に利用し、アプリ内の情報へアクセスする。パスワード窃取とは異なり、既存のログイン状態が悪用の足場になる点が重要となる。

共有リンク

通常は特定の内容を閲覧させるための入口となる。リンクを開くことでコード実行まで起きるなら、単なる閲覧権限の共有とはリスクが異なる。

深掘り解説

ログイン中のブラウザーは認証情報と同じく扱う

ブラウザーのログイン状態は、利用者が毎回パスワードを入力しなくてもサービス上の操作を可能にする。このため、セッション内でコードを動かされる問題では、パスワードが盗まれていなくても、会話の閲覧など利用者の権限で可能な操作が悪用され得る。共有リンクは内容を読むだけのものと思い込まず、ログイン中の画面で開くリンク自体を攻撃経路として評価する必要がある。例えば、利用者から「不審な共有リンクを開いた」と連絡があった場合、受信者全員への注意喚起だけで終えず、実際に開いたか、開いた時点でログインしていたか、業務上の機微情報を扱うアカウントかを切り分ける。該当する場合は、サービス側の修正適用状況を確認し、利用可能な記録で不審なアクセスを調べ、必要に応じてセッションを失効させる。記録がないことを、情報閲覧がなかった証拠として扱わない点も重要となる。
