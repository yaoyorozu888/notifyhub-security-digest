VU#385711: PrestaShop Performance Debug Configuration Contains a PHP Code Injection Vulnerability

🗞️ CERT/CC 🕒 2026-11-09T23:53:28+09:00 🔗 原文を開く
Impact: High Vulnerability
原文リンク 日次トップ

Impact判定理由

管理画面の設定変更権限とPHPによる設定ファイル書き込みが必要だが、成立時はアプリケーション権限でコードが実行され、顧客情報や店舗運営に波及し得る。 CERT/CCの脆弱性公表で修正版も提示されている一方、悪用確認や影響版の範囲は不明なため、実悪用を示す公的シグナルとしての上乗せは行わずHighとする。

🧾 要約（ChatGPT / gpt-6-luna）

概要

PrestaShopの管理画面にある性能設定のデバッグ機能で、認証済み利用者が設定値を通じてPHPコードを注入できる脆弱性がCERT/CCから公表された。攻撃者はデバッグ用Cookieの名前や値に細工し、PHPプロセスが書き込める設定ファイルへ実行可能なコードを混入させ、後続のリクエストで実行させる。成立には、対象設定を変更できる管理画面アカウントと、PHPプロセスによる設定ファイルへの書き込みが必要で、CSRF対策だけでは権限を持つアカウント自体の悪用を防げない。実行権限はPHPプロセスの範囲に限られるが、アプリケーションの秘密情報や顧客データへのアクセス、ファイルやデータベースの改変、店舗運営の妨害につながり得る一方、OS管理者権限の取得やOSコマンド実行は自動的には成立しない。修正版は9.2.1で提供され、影響する旧版の範囲と実際の悪用状況は未確認のため、該当設定の変更権限、設定ファイルの書き込み権限、侵害の痕跡を確認し、更新可能性と業務影響を並行して評価する必要がある。

📌 キーワード解説

PHPコード注入（PHP code injection）

入力値がデータではなくPHPの命令として実行される状態を指す。画面への文字列表示とは異なり、実行権限で処理が動く点が重要となる。

CSRF（クロスサイトリクエストフォージェリ）

利用者のブラウザーに意図しない操作を送らせる攻撃で、権限を持つ利用者本人の設定変更を防ぐ仕組みではない。

PHPプロセスの実行権限

注入コードが利用できるファイルや機能は、PHPを動かす実行主体の権限に依存する。OS管理者権限の取得とは区別して評価する必要がある。

深掘り解説

設定値を実行可能な設定ファイルへ書き込む危険

設定画面の値であっても、保存先がPHPソースのような実行可能ファイルなら、通常のデータ保存とは異なる信頼境界が生じる。値を引用符で囲むだけでは不十分で、PHP構文として安全に生成する処理が必要になる。入力検証と出力時の文脈に合ったエスケープを行い、可能なら設定を実行コードではなくデータ形式で保存する。例えば、管理者がデバッグ用Cookieの値を入力でき、その値をPHPの定数定義へ直接連結する設計では、入力が文字列の範囲を抜けて命令として解釈される恐れがある。運用上は、管理画面の権限確認に加え、設定ファイルの所有者・書き込み権限、更新前後の差分、予期しない構文や改変時刻を調べる。書き込みを止める緩和策は正規の設定変更も妨げるため、適用前に変更手順と復旧手段を確保する。
