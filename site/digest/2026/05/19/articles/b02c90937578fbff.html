Infostealer（情報窃取マルウェア）

端末内の秘密情報を盗むマルウェア。ランサムウェアと違い、暗号化より認証情報の横取りを優先する。

有名名称の打ち間違いを狙う手口。依存関係混同と違い、利用者の入力ミスや目視確認漏れに依存する。

ビルドやデプロイ用のトークンや鍵。端末のパスワードより権限範囲が広く、成果物改ざんに直結しやすい。

悪性 npm パッケージで最初に見るべき実行点

npm 由来のサプライチェーン侵害では、パッケージ名の怪しさだけでなく「いつコードが動くか」を押さえる必要がある。典型的な実行点は、利用アプリがそのモジュールを import した瞬間、またはインストール時に走る lifecycle script となる。後者は特に厄介で、アプリケーションの本番コードに到達する前に、開発端末や CI ランナー上で処理が始まる。 具体例として、開発者が <code>npm install chalk-tempalte</code> のような誤記パッケージを追加した場合、<code>package.json</code> の <code>postinstall</code> が外部スクリプトを取得し、環境変数から GitHub token や npm token を送信する流れが成立し得る。この場合、アプリのテスト失敗やユーザー影響が出る前に、リポジトリ書き込み権限や公開権限が奪われる。 CSIRT の初動では、端末 EDR の検知だけに寄せず、<code>package-lock.json</code>、<code>npm-shrinkwrap.json</code>、CI のジョブログ、npm プロキシや Web プロキシの外向き通信を突き合わせると判断が速くなる。該当パッケージの有無だけで終わらせず、インストール時刻の前後で発行・利用されたトークン、パッケージ公開、リポジトリ更新、CI 変数参照の履歴まで確認する必要がある。封じ込めではパッケージ削除より先に、影響を受けた可能性のあるトークンを失効し、CI ランナーの再作成やキャッシュ破棄を行う方が安全側に倒せる。
