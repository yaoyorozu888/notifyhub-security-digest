概要

CISA KEV に CVE-2010-0806 が掲載されており、Microsoft Internet Explorer の Use-After-Free 脆弱性が実際に悪用された既知事例として扱われている。攻撃は、脆弱な Internet Explorer で細工された Web ページや誘導先を開かせ、解放済みメモリの再利用を通じて利用者権限でコード実行へつなげる形になりやすい。端末侵害後は認証情報窃取、プロキシ経由の内部探索、古い業務端末からの横移動に広がる可能性があり、特に レガシー業務端末 と 未管理ブラウザ が焦点になる。CVE-2010-0806 は古い脆弱性で、NVD では CVSS v2 9.3 として扱われるが、2026年時点の体感リスクは Internet Explorer または脆弱な実装が実運用に残っているかで大きく変わる。未確認事項は、今回の KEV 更新が新規悪用観測に基づくものか、期限や対象製品の整理更新なのか、また Microsoft Edge の IE モードや MSHTML 利用コンポーネントまで直接影響するかという点になる。初動では資産管理、EDR、プロキシログから IE 実行実績 と古い Windows 端末を確認し、該当端末の隔離、パッチ適用、IE 起動制御、業務代替手段の有無を並行して判断する必要がある。

深掘り解説

古いクライアント脆弱性を KEV でどう優先度付けするか

古いブラウザ脆弱性は、公開年だけを見ると優先度を下げたくなる。しかし KEV に載る場合、少なくとも過去または現在に実攻撃で使われた事実があり、脆弱性管理では「理論上の危険」ではなく「攻撃手口として成立済み」と扱う必要がある。 判断の軸は三つに分けるとぶれにくい。第一に、該当ソフトが本当に残っているか。Internet Explorer は標準ブラウザでなくても、古い業務アプリ、検証端末、製造系端末、閉域風ネットワークの運用端末に残ることがある。第二に、利用者が外部または攻撃者制御コンテンツを開けるか。プロキシで外向き通信が制限されていても、メール添付の HTML、内部に置かれた改ざんページ、踏み台端末からの誘導で成立する場合がある。第三に、侵害後の到達範囲。端末がドメイン参加し、共有フォルダや管理ツールにアクセスできるなら、ブラウザ脆弱性でも組織内侵入の入口になりうる。 具体例として、資産台帳上は Internet Explorer が廃止済みでも、プロキシログに <code>MSIE</code> や古い Trident 系の User-Agent が残っている場合、対象端末を抽出して EDR のプロセス履歴、パッチ状態、利用者業務を突き合わせる。すぐに削除できない端末では、外部 Web への直接通信遮断、IE 実行禁止、業務サイトの許可リスト化、端末のネットワーク分離を組み合わせる。単に「古い CVE だから低い」とせず、「残存資産」「誘導経路」「侵害後の権限」の三点で評価すると、実運用上の優先順位を決めやすくなる。
