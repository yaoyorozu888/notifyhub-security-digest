概要

ScanNetSecurityは、IPAがPSIRTの体制整備と運用支援を無償で実施する旨を伝えている。脆弱性そのものの公表や悪用観測ではなく、製品・サービス提供組織が脆弱性受付、影響判定、修正調整、顧客通知を回すための支援施策として読むべき内容となる。直接の悪用手口は示されていないが、PSIRT不在の組織では、報告された脆弱性のトリアージ遅延、修正版提供の混乱、顧客向け説明の不整合が起き、攻撃者に修正前の猶予期間を与えやすい。影響範囲は社内CSIRTだけに閉じず、開発、品質保証、法務、広報、営業、保守委託先まで広がり、製品が顧客環境に組み込まれている場合はサプライチェーン上の調整課題にもつながる。入力情報からは、支援対象、募集条件、実施期間、成果物、個別脆弱性対応への関与範囲は確認できず、自組織で活用可否を判断するにはIPA一次情報の確認が必要となる。

📌 キーワード解説

PSIRT（Product Security Incident Response Team／製品セキュリティ対応組織）

製品脆弱性の受付から修正公開までを担う。社内端末事故を扱うCSIRTとは責任境界が異なる。

CSIRT（Computer Security Incident Response Team）

組織内の侵害対応を主に扱う。PSIRTと混同すると、顧客向け修正調整が抜けやすい。

CVD（Coordinated Vulnerability Disclosure／協調的脆弱性開示）

発見者と提供者が公開時期を調整する考え方。即時公開や秘匿放置とは異なる。

深掘り解説

PSIRTとCSIRTを分けて考える理由

CSIRTは主に自組織の環境を守る機能として設計される。一方、PSIRTは自組織が提供する製品やサービスの脆弱性に責任を持つ機能となる。この違いは、インシデントの境界が社内ネットワークで止まるか、顧客環境まで広がるかに表れる。 例えば、自社製VPNアプライアンスに認証回避の脆弱性が見つかった場合、CSIRTだけで対応すると、社内で使っている機器の遮断やログ確認には進める。しかし顧客へ提供済みのファームウェア、保守契約先への通知、修正版の検証、CVE採番、回避策の表現、公開日の調整までは別の運用が必要となる。ここを曖昧にすると、顧客ごとに説明が食い違い、攻撃者にとっては未修正資産を探しやすい状態が残る。 実務上は、PSIRTを大きな組織名として作ることより、受付窓口、深刻度判定、開発部門へのエスカレーション、公開判断、顧客通知、修正後の悪用監視を誰が承認するかまで決めるほうが重要となる。CSIRTは攻撃観測や侵害有無の確認に強く、PSIRTは製品修正と外部調整に強い。この二つを接続しておくと、脆弱性公表後に社内外のログから悪用有無を確認し、顧客向けの注意喚起にも反映できる。
