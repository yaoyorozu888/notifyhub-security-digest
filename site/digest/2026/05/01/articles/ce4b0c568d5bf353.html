概要

Googleは、Gemini CLIおよび関連するGitHub Actionsワークフローに存在した重大なリモートコード実行（RCE）脆弱性（CVSS 10.0）を修正した。この欠陥は、攻撃者が細工した設定ファイルを読み込ませることで、ホスト環境上で任意のコマンドを実行できるものであり、CI/CDパイプラインを通じて自動的に実行されるケースでは被害範囲が広がりやすい。特に、権限のない外部入力をCIジョブに渡す構成を持つリポジトリでは、リポジトリ全体の機密情報や署名鍵の漏えいにつながる可能性がある。現時点では悪用の公的確認はないが、PoC作成が容易な構造であり、サプライチェーン経由の侵入に転用されるリスクがある。CSIRTとしては、依存パッケージの更新に加え、CI環境の権限分離とSecrets管理の再点検が求められる。

📌 キーワード解説

RCE（Remote Code Execution）

リモートから任意コードを実行される脆弱性。情報漏えい型と異なり、攻撃者がシステム制御を奪取できる点が本質。

CI/CDパイプライン

継続的インテグレーション／デリバリの自動化環境。利便性の反面、権限集中により1点突破で広範な影響が出やすい。

GitHub Actions

GitHub上でCI/CDを自動化する仕組み。外部アクション利用時はコード供給元の信頼性が重要となる。

サプライチェーン攻撃

依存パッケージやビルド工程を悪用して侵入する手法。直接攻撃より検知が難しく、CI環境が標的になりやすい。

深掘り解説

CI環境における権限境界の再設計

CI/CD環境は利便性のために広範な権限を持つことが多く、1つの脆弱なステップが全体の侵害につながる。今回のGemini CLI脆弱性のように、外部入力を設定として読み込む仕組みでは、攻撃者が任意コードを注入できる。実務では、(1) CIジョブごとに異なるトークンを発行し、(2) Secretsを最小限に限定し、(3) 外部アクションを固定バージョンで参照する、などの防御策が有効である。例えばGitHub Actionsでは、`permissions:`フィールドで不要な権限を明示的に無効化することで、万一のRCE発生時にも被害を局所化できる。CIは「開発者の自動化環境」ではなく「本番相当の権限を持つ実行基盤」として扱うべきである。
