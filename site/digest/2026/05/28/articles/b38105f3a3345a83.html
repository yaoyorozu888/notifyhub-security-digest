概要

The Hacker News が、OX Security の調査として、npm レジストリ上の悪性パッケージ mouse5212-super-formatter が情報窃取機能を備えていたと報じた。このパッケージは Anthropic の Claude がアップロードや出力の処理に使う /mnt/user-data 配下のファイルを収集し、GitHub 経由で外部へ送る設計とされ、開発環境に置かれたAI利用時の中間成果物や投入データが漏れる恐れがある。悪用は、開発者がフォーマッタ等の無害な依存関係として導入することが前提になり、ビルド端末や検証コンテナが社内リポジトリ、トークン、顧客データを扱う場合は、単一端末の窃取からソースコード・秘密情報の流出へ広がる。ただし、現時点でインストール件数、被害組織、GitHub 側の受信先、持続化機能や認証情報窃取の有無は記事情報だけでは確認できない。CSIRTは npm依存関係の混入 と AI作業ディレクトリの機微性 を分けずに扱い、該当パッケージの利用有無、開発端末からGitHubへの不審通信、Claude関連ディレクトリへの読み取り挙動を優先して確認するとよい。

深掘り解説

AI作業ディレクトリを機密領域として扱う理由

AI連携の開発環境では、利用者が意識して保存したファイルだけが機密情報ではない。Claude のようなツールは、アップロードされた資料、生成物、処理途中の一時ファイルを専用ディレクトリに置くことがあり、そこには「正式な成果物ではないが外部に出せない情報」が集まりやすい。従来のDLPやリポジトリ監査は Git 管理下のファイルや既知の秘密情報に寄りがちで、AI作業ディレクトリは監視対象から漏れやすい。具体例として、開発者が検証用コンテナで不明な npm パッケージを試し、同じ環境からClaudeに設計書をアップロードしていた場合を考える。パッケージが実行時に /mnt/user-data を走査できれば、ソースコードを直接盗まなくても、設計書、テストデータ、モデルへの指示文、出力結果をまとめて外部送信できる。これは「AIツールの問題」だけではなく、開発端末上の任意コード実行とデータ配置の問題になる。運用上は、未評価パッケージの検証環境とAI利用環境を分ける、検証時は外向き通信を既定拒否にする、AI作業ディレクトリをEDR/DLPの監視対象に加える、といった分離策が効く。パッケージ名のブロックだけでは再公開や名称変更に弱いため、npm install 後の不審なファイル走査、GitHub や匿名ストレージへのアップロード、短時間の大量読み取りを組み合わせて見る必要がある。
