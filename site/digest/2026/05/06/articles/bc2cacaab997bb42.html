概要

中国の企業向けOAプラットフォームWeaver E-cologyにおいて、CVE-2026-22679（CVSS 9.8）の認証不要RCE脆弱性が確認され、すでに実際の攻撃が観測されています。脆弱性はDebug API（/papi/esearch/data/devops/）の不適切な入力処理に起因し、攻撃者はHTTP経由で任意コマンドを実行可能です。影響範囲はE-cology 10.0の20260312以前の全バージョンで、外部公開されたOAサーバを踏み台に内部ネットワークへ横展開されるリスクがあります。攻撃者は主に中国国内外の企業を標的に、Webシェル設置や認証情報窃取を行う事例が報告されています。現時点で脆弱性の詳細PoCは限定的ですが、スキャン活動の増加が確認されており、未更新環境は即時遮断・更新が推奨されます。

📌 キーワード解説

RCE（Remote Code Execution）

リモートから任意コードを実行される脆弱性。情報漏えいよりも被害範囲が広く、踏み台化や持続化に直結する。

Debug API

開発・検証用に内部情報へアクセスするAPI。運用環境で無効化されていない場合、攻撃面を大きく広げる。

Webシェル

攻撃者が設置するリモート操作用スクリプト。正規通信に偽装しやすく、検知を困難にする。

横展開（Lateral Movement）

侵入後に内部ネットワークへ拡散する行為。単一サーバ侵害から全社的被害へ発展する起点となる。

深掘り解説

Debug APIを残したまま運用するリスクの本質

開発時に利用されるDebug APIは、通常の認証や入力検証をバイパスできる設計になっていることが多い。製品リリース時にこれを無効化し忘れると、攻撃者にとっては“裏口”として機能する。特にOAやERP製品のように社内ネットワークへ広い権限を持つシステムでは、1台の侵害が全社的な情報流出につながる。具体例として、今回のWeaver E-cologyでは/papi/esearch/data/devops/が外部から直接呼び出せる状態で残存しており、コマンド実行を許していた。CSIRTとしては、脆弱性対応だけでなく、運用中のWebアプリで不要なAPIやデバッグエンドポイントが存在しないかを定期的に棚卸しすることが重要である。WAFやリバースプロキシでのアクセス制御も有効だが、根本的にはアプリケーション側での無効化が必須である。
