概要

PowerDNS Authoritative Server において、特別に作成された DNS パケットを受けると、メモリ不足や過剰な CPU 負荷が発生する脆弱性が報じられている。認証を必要としない通信経由で資源を枯渇させられるなら、公開中の権威 DNS に対して 拒否サービス を起こせる余地がある。影響は単一サーバの停止にとどまらず、冗長構成でも同時に同種の問い合わせを受けると、名前解決全体の不安定化へ広がる可能性がある。公開情報の範囲では、悪用の成立条件、対象となるバージョン、既知の実被害は未確認であり、修正有無と再現条件の確認が必要になる。

📌 キーワード解説

権威 DNS サーバ

ゾーン情報の正答を返す役割を持つ。再帰 DNS と違い、外部からの大量問い合わせで資源を消耗しやすい。

メモリ不足

枯渇するとプロセス停止や再起動に直結する。単なる遅延より、サービス断へ進みやすい。

CPU 負荷

高負荷が続くと応答遅延が連鎖する。帯域不足より、少量の悪性パケットでも成立しやすい。

深掘り解説

権威 DNS の資源枯渇は「止まる範囲」を先に見る

権威 DNS の脆弱性を評価するときは、攻撃が成功するかだけでなく、どこまで止まるかを先に見る必要がある。単一ノードが落ちても冗長化で吸収できる場合がある一方、同じ実装を使う複数ノードが同時に負荷を受けると、名前解決が広域で不安定になる。 具体例を挙げると、外部公開の権威 DNS が 2 台冗長で動いていても、両方が同じ入力処理の欠陥を持つなら、攻撃者はそれぞれに負荷をかけて片方ずつ再起動を誘発できる。ここで重要なのは、監視が「稼働中」を示していても、応答遅延や一時的な SERVFAIL が増えれば実害が出る点にある。 初動では、脆弱バージョンの有無だけでなく、再起動履歴、CPU 飽和、メモリ逼迫、権威応答率の低下を確認する。加えて、DNS ファイアウォールや前段のレート制御で外部からの異常な問い合わせを抑えられるかも見ておくと、パッチ適用までの時間を稼ぎやすい。
