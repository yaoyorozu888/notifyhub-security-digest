📌 キーワード解説

再帰 DNS（recursive DNS）

利用者の代わりに名前解決を代行する仕組み。権威 DNS への攻撃と違い、組織内の通信全体に遅延が広がりやすい。

CPU 負荷

処理能力を使い切らせる攻撃で、サービス停止に直結しやすい。枯渇系のメモリ不足と違い、再起動後も同じパケットで再発しやすい。

メモリ不足

異常な入力でメモリ確保が膨らみ、処理が落ちる状態。情報漏えいより可用性侵害が主眼で、DoS と結び付いて見る必要がある。

深掘り解説

DNS で可用性障害が全体障害に変わる理由

DNS の障害は、単に名前解決が失敗するだけで終わらない。多くの業務システムは、外部 SaaS、認証基盤、更新サーバ、監視基盤まで DNS に依存しているため、一つの recursor が詰まると、利用者からは「ネットワーク全体が壊れた」ように見える。 実務で厄介なのは、障害の入口がアプリではなく DNS にある点になる。たとえば、ある拠点で Web が遅いという通報があっても、実際には DNS の応答遅延が原因で、アプリや回線の調査だけを進めると遠回りになる。特別に作成された DNS パケットで CPU が上がる型の問題では、ログに明確なエラーが残らないこともあるため、再帰 DNS の応答時間、ワーカースレッドの詰まり、メモリ使用量、再起動直後の再発有無を並べて見る必要がある。 封じ込めでは、外部から recursor へ直接到達できる経路をまず絞る発想が重要になる。たとえば、社内向け recursor を誤ってインターネット公開していたなら、アクセス制御で入口を閉じるだけでも被害を抑えやすい。一方で、拠点や VPN 利用者がその recursor に依存している場合、単純停止は業務影響を広げるので、代替 DNS への切り替え手順を先に確認しておく必要がある。DNS の脆弱性対応は、修正適用だけでなく、どこに依存しているかの棚卸しまで含めて初めて完結する。
