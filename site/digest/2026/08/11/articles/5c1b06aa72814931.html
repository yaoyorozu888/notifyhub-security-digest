VU#614868: Opencart ecommerce platform contains directory traversal vulnerability

概要

OpenCart v4.2.0.0 の拡張機能インストーラに、ディレクトリトラバーサルの脆弱性が見つかった。アップロードされた .zip の展開時に、展開先が意図したディレクトリ内かを検証せず、../ を含むファイル名をそのままファイルパスとして扱ってしまう。攻撃者は悪意ある拡張機能を用意し、管理者がそれをインストールすると、webroot へのファイル書き込みを通じて PHP web shell を配置できる可能性がある。結果として、OpenCart が持つ権限でのリモートコード実行に近い状況へ進み、システムコマンド実行や横展開の足掛かりになりうる。確認済みなのは v4.2.0.0 で、他の 4.x 系への影響は未確認事項として残る。

📌 キーワード解説

ディレクトリトラバーサル

本来の保存先を越えてファイルを書かせる欠陥を指す。単なるアップロード不備と異なり、任意配置から実行までつながる点が危険になる。

web shell

ブラウザ経由でサーバ上の操作を受け付ける不正スクリプトを指す。権限の弱いファイル書き込みが、そのまま実行権限の獲得に変わる場面で問題になる。

拡張機能インストーラ

機能追加用パッケージを展開・配置する処理を指す。更新機能と混同しやすいが、外部入力をそのままファイル操作へつなぐため、検証不備の影響が大きい。

深掘り解説

ZIP 展開時のパス検証は「保存」ではなく「境界の強制」と捉える

この事案の本質は、ZIP を解凍する機能が単なるファイル保存ではなく、**任意のパス操作**に化けた点にある。攻撃者は、ファイル名に <code>../</code> を入れて本来の展開先の外へ抜け、例えば <code>webroot</code> 配下に PHP ファイルを置く。ここで重要なのは、入力値の文字列チェックだけでは不十分なことだ。正規化後の最終パスが許可されたディレクトリ内に収まるかを、展開前ではなく**実際の解決結果**で確認する必要がある。 具体例を挙げると、管理画面から「テーマの追加」や「拡張機能の導入」を許可している環境で、担当者が見た目だけでは正常に見える ZIP を取り込んだ場合でも、内部に悪意あるパスが混ざっていれば、展開時に実行可能ファイルが配置される。しかも、管理者の操作がトリガーになるため、WAF や一般的な外向き通信監視だけでは見逃しやすい。 運用上は、アップロード機能の有無よりも、**展開後にどこへ書けるか**を管理する発想が重要になる。アプリケーション実行ユーザーに最小権限を与え、書き込み先を限定し、展開処理で正規化済みパスの検証を行う。加えて、拡張機能の導入は信頼できる配布元に限定し、管理画面の操作ログとファイル整合性を定期確認する流れが、初動の封じ込めに効く。
