概要

miChecker に XML 外部実体参照（XXE）に関する脆弱性が公表された。XML の解釈時に外部実体を処理できる構成では、攻撃者が細工した入力を送ることで 本来参照させない内部情報の読取 や、外部通信を起点にした情報流出が起こりうる。認証前の入力受付箇所 か、ファイル取込や自動処理の経路にあるかで実害の大きさが変わる。影響はまず情報漏えいが中心になりやすいが、設定や周辺機能次第では内部ネットワークの探索に踏み台として使われる余地もある。現時点では、悪用の有無、影響を受ける版、既定設定で外部実体が有効かどうかは未確認のため、そこを切り分けて評価する必要がある。

📌 キーワード解説

XXE（XML External Entity）

XML の外部参照を悪用して情報を抜く手口。単なる入力検証不備より、内部ファイル読取や外部通信につながりやすい。

認証前入力

ログイン前に受け付ける入力経路を指す。認証後の機能より露出が広く、同じ欠陥でも被害が大きくなりやすい。

外部実体

XML が外部の資源を読む仕組み。便利な機能だが、無効化されていないと SSRF や情報流出の入口になりやすい。

深掘り解説

XML 処理では「入力を読む」だけでなく「外部へ触れないか」を見る

XML の脆弱性対応で見落としやすいのは、構文が正しいかではなく、処理系が外部へ何を取りに行くかという点になる。XXE は、攻撃者が XML に外部参照を埋め込み、アプリケーションに内部ファイルや社内向けの URL を読みに行かせる形で成立する。見た目はただのデータ投入でも、裏ではサーバが外部に接続してしまうため、通常の入力検証だけでは止めにくい。具体例として、経費申請の取り込み機能が XML を受け付ける場合、攻撃者が `file:///etc/passwd` のような参照を混ぜると、処理結果やエラー経路を通じて情報が漏れることがある。ここで重要なのは、被害が「その画面の入力欄」だけに閉じない点になる。ファイル取込、API、バッチ、連携基盤など、XML を解析する入口が複数あると、1 か所の修正漏れが残りやすい。実務では、XML パーサの外部実体解決と DTD を無効化する設定確認、失敗時の外部通信監視、そして不要な XML 受付自体の停止を並行して考える必要がある。
