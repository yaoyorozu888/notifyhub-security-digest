概要

Elementor Pro の WordPress プラグインに、認証なしで PHP ファイルをアップロードされるおそれがある脆弱性が公表された。成功すると リモートコード実行 につながり、改ざん、情報窃取、踏み台化まで進む可能性がある。攻撃の起点はフォーム機能のファイル処理とみられ、一般公開サイトで有効な構成なら攻撃者の狙い所になりやすい。CVE-2026-32475 は CVSS 9.0 とされるが、実運用上は「外部公開中の WordPress があるか」「該当機能が有効か」「修正済みか」で影響が大きく変わる。記事断片だけでは、影響を受けるバージョン範囲、既知の悪用有無、修正版の有無は未確認である。

深掘り解説

WordPress のファイルアップロード脆弱性は「保存」より「実行可能性」で見る

ファイルアップロードの不備は、単に不要なファイルが置かれるだけでは終わらない。危険なのは、置かれたファイルが Web サーバ上で<strong>実行できる場所</strong>に入ることにある。画像や文書として受け付けたつもりでも、拡張子検査だけなら容易にすり抜けられる。 たとえば、問い合わせフォームから送られた添付を <code>/wp-content/uploads/</code> に保存し、その配下で <code>.php</code> が動く構成なら、攻撃者は小さな PHP を置くだけで任意コマンド実行へ進める。逆に、同じファイルを置けても、Web からは静的配信のみで実行不可なら被害は大きく下がる。 実務では「アップロード可否」だけでなく、保存先の権限、実行禁止設定、MIME 判定、拡張子の正規化、生成ファイル名の制御をまとめて確認する必要がある。特にプラグインやテーマの更新で、以前は無害だった保存先が実行可能になることがあるため、修正時は機能テストと同時にデプロイ設定も見直す流れが要る。 初動で見るべき点は、Web アクセスログに不自然なアップロード後の即時参照がないか、`uploads` 配下に PHP や不審な長いランダム名のファイルがないか、改ざん検知で新規スクリプトが出ていないかである。WordPress は運用者が多く、外部委託や古いプラグインが残りやすいため、脆弱性の有無より先に「実行できる置き場があるか」を押さえると判断がぶれにくくなる。
