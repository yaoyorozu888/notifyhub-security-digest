概要

本記事は、Microsoft Graph と PowerShell を使って、M365 や Entra 上の情報を収集し、休眠アカウント や 未使用ライセンス を洗い出す観点を扱う。正規の管理機能を使うため、攻撃者が認証情報を得た後の調査や横展開の前段としても悪用しやすい。特に、権限が広い管理アプリや運用スクリプトが残っている環境では、資産把握と情報収集が短時間で進みやすい。影響は単発の閲覧にとどまらず、権限や利用状況の把握から、後続の不正操作や退避先の探索に広がる可能性がある。なお、記事は技術解説寄りであり、実際の悪用事例や検知指標の詳細は本文だけでは未確認である。

📌 キーワード解説

Microsoft Graph

M365 と Entra をまとめて扱う API で、旧来の個別 API より横断的な情報取得に向く。単なる参照口ではなく、権限次第で設定変更まで届く点が重要になる。

休眠アカウント

長く使われていないが無効化されていないアカウントを指す。未使用アカウントと違い、権限やライセンスが残るため侵入口として残りやすい。

Entra

旧 Azure AD を含む ID 基盤で、認証と権限管理の中心になる。端末管理よりも、まず誰が何に入れるかを決める層として見る必要がある。

深掘り解説

管理 API の強みは可視化と同時に横断権限を持つ点にある

Microsoft Graph のような管理 API は、単一画面では見えない情報をまとめて取れるため、運用では非常に便利になる。一方で、攻撃者にとっても同じ利点がある。認証情報を得たあと、メール、ユーザー、端末、ライセンスの状態を短時間で集められるから、次の一手を決めやすくなる。 ここで重要なのは、危険性が「API そのもの」ではなく、「どの権限をどの主体に与えているか」にある点になる。たとえば、監査目的のつもりで広い読み取り権限を付けた管理アプリがあるとする。平時は問題がなくても、そのアプリ秘密鍵や証明書が漏れれば、組織の棚卸し情報が一括で持ち出される。休眠アカウントや未使用ライセンスの一覧は一見無害に見えるが、攻撃者から見れば「使われていないが消されていない入口」や「防御の薄い部門」を探す手掛かりになる。 具体例を挙げる。ある組織で、外部委託先の自動棚卸しスクリプトに Graph の読み取り権限を付与していたとする。スクリプト自体は資産管理に使われているだけでも、保存された資格情報が漏れると、攻撃者は休眠アカウント、管理者の所属、端末一覧を収集できる。そこから、長期間ログインしていない管理者アカウントを狙う、未使用ライセンスを使う想定で調査を深める、特定部門の端末だけを重点的に調べる、といった動きにつながる。結果として、侵入の足場作りが静かに進む。 CSIRTとしては、Graph 利用の有無よりも、まず「誰が」「どの権限で」「どの自動化経路から」アクセスしているかを押さえる必要がある。特に、証明書ベースのアプリ認証、長寿命の秘密情報、無人実行の棚卸し処理は、侵入後の情報収集に転用されやすい。検知は、通常の運用時刻と異なる大量照会、初見のアプリからの広範な読み取り、休眠アカウントを列挙するような連続クエリの有無を確認する流れが現実的になる。
