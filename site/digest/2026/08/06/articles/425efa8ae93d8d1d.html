Critical Gitea Flaw Let Unauthenticated Attackers Read Server Files via Org-Mode Markup

Impact判定理由

認証不要で任意ファイルの読み取りに至る可能性があり、秘密鍵や設定ファイルが読めれば侵害の起点が広がる。公開リポジトリと細工したマークアップだけで成立するとされ、入口が非常に広い。The Hacker News は二次情報だが、CVE と修正版の提示があり、深刻度の引き下げ要因は小さいため Critical を維持する。

🧾 要約（ChatGPT / gpt-5.4-mini-2026-03-17）

概要

Gitea の 認証不要のファイル参照 問題が報じられた。公開リポジトリに細工した Org-mode マークアップを置くだけで、攻撃者は Gitea が動作時に読める 任意のサーバーファイル を取得できる可能性がある。ログインも書き込み権限も不要で、対象は 1.22.1 から 1.27.0 までとされ、修正版は 1.27.1 となる。CVE-2026-59774 は Critical、CVSS 9.8 とされるが、実運用ではファイルの中身次第で秘密情報漏えいの質が大きく変わる。未確認事項として、記事だけでは実際の悪用有無、露出している Gitea の範囲、読み取られうる設定ファイルや鍵の具体例は確定していない。

📌 キーワード解説

Org-mode マークアップ

文書中の記法を使って表示や処理を変える仕組み。通常の本文表示と違い、解析側が解釈を誤ると意図しない参照に化けやすい。

認証不要

ログインせずに到達できる状態を指す。認証済みの不正利用より入口が広く、外部公開面で最優先の確認対象になる。

サービスアカウント

アプリが動作に使う権限主体。人の権限より広いことがあり、読み取り可否がそのまま漏えい範囲を決める。

深掘り解説

権限境界は「ログイン可否」ではなく「実行主体の読める範囲」で決まる

今回の論点は、攻撃者が管理者権限を取ったかではなく、Gitea が内部で使う権限を使ってどこまで読めてしまうかにある。ここを見誤ると、見た目は単なる表示機能の不具合でも、実際には設定ファイル、秘密鍵、トークン、接続先情報の漏えいに直結する。 実務では「外からの入力を、どの権限で、どの処理系が解釈するか」を分けて考える必要がある。たとえば、公開リポジトリ上の文章がレンダラに渡され、レンダラがファイル参照系の記法を解釈すると、閲覧機能がそのままサーバー内部の読み取り窓口になる。今回のような脆弱性は、Web アプリの権限ではなく OS 上のプロセス権限まで影響範囲を広げる。 具体例として、Gitea がアプリ設定や SSH 関連の秘密情報を読める権限で動いていると、漏えいしたファイル次第でリポジトリの改ざん、秘密鍵の悪用、他基盤への横展開に発展しうる。したがって、パッチ適用だけで終わらせず、サービスアカウントの権限最小化、秘密情報の配置分離、公開リポジトリの監査を同時に進める必要がある。
