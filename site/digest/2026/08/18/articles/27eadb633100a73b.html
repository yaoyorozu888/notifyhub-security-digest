概要

MCP サーバーが、平文の設定ファイル、過剰な権限設定、prompt injection を通じて企業の秘密情報を露出させうる、という注意喚起の記事である。AI エージェントが業務システムに接続されるほど、認証情報や内部データへの到達点が増え、従来の境界防御だけでは見えにくい露出が起きる。特に、サーバーの稼働が セキュリティ部門に把握されないまま 進むと、漏えいは設定不備の発見遅れから静かに拡大する。悪用の成立には、MCP サーバーの実運用、秘匿情報を含む設定や接続先、エージェントへの過剰権限が前提となるが、記事本文では具体的な侵害事例や被害範囲の実測は示されていない。したがって、個別の攻撃キャンペーンというより、AI 導入時の構成ミスと可視化不足 が生む漏えいリスクとして扱うのが妥当である。

📌 キーワード解説

MCP（Model Context Protocol）

AI エージェントが外部ツールやデータへ接続するための共通手順。API 直結より便利だが、権限設計を誤ると横断的な秘匿情報露出につながる。

prompt injection

指示文に紛れた悪意ある内容で AI の判断を誘導する手口。単なる入力検証不備と違い、会話や文書の中から間接的に命令される点が厄介になる。

過剰権限

必要以上の操作権限を与えた状態。最小権限と対比すると、誤動作や誘導が起きた際の漏えい範囲が一気に広がる。

深掘り解説

AI 接続基盤は「使えること」より「見えて止められること」を先に設計する

MCP のような接続基盤では、便利さが先に立つと、どのサーバーが何の権限で何に触れているかが後回しになりやすい。ここで重要なのは、AI が何を読めるかだけでなく、誰がその接続を登録し、どの設定ファイルに秘密情報が残り、異常時にどこで止めるかを運用に落とすことになる。 具体例として、社内の問い合わせ対応エージェントがチケットシステムと文書保管庫に接続している場合を考える。設定ファイルに API キーが平文で置かれ、さらに文書保管庫への読み取り権限が広すぎると、攻撃者はエージェントそのものを乗っ取らなくても、誘導文を混ぜた文書を読ませるだけで内部情報を引き出せる。つまり、侵害点は AI の画面ではなく、設定、認可、接続先の三層に分かれて現れる。 実務では、まず接続一覧を資産として棚卸しし、各接続に対して「必要最小の権限」「秘密情報の保管場所」「監査ログの取得先」をセットで確認するのが有効になる。新しい MCP サーバーを追加するたびに、通常のアプリ追加と同じく変更管理に載せ、誰が承認したか、どのデータに触れるか、停止手順があるかを残すべきになる。AI 活用はスピードが評価されやすいが、止める設計がなければ、漏えいが起きたときに初動が遅れやすい。
