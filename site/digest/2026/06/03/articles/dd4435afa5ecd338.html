概要

CERT/CC は、Collibra Agent における 未認証で到達可能なREST機能 と ZIP展開時のパストラバーサル を連鎖させ、リモートからコード実行に至る脆弱性を公開した。対象は Collibra Platform と Collibra Platform Self-Hosted の Agent で、/rest/* の認証・認可不備により攻撃者が環境情報や書き込み先の手掛かりを得たうえで、POST /rest/restore に細工したZIPを投入できる。任意ファイル書き込みが Web 公開ディレクトリへの悪意ある JSP 配置につながると、Web shell設置、アプリケーションデータの改ざん、可用性低下、周辺環境への踏み台化まで広がる。特に Agent が Web UI とは別ポートで動き、インストーラ設定に反して全インターフェースへバインドする挙動が観測されているため、管理者が閉域と考えていた構成でも露出確認が必要となる。CVE-2026-10622 と CVE-2026-10621 が示されているが、CVSSスコアは本文中に記載されていない。未確認事項は、実際の悪用有無、インターネット露出台数、SaaS各テナントでの修正適用状況、JSP配置以外の実行経路となる。

深掘り解説

Zip Slipが任意ファイル書き込みからRCEへ変わる境目

Zip Slipの本質は、ZIP内のファイル名を単なる保存名ではなく、展開時の書き込み先パスとして信頼してしまう点にある。圧縮ファイルのエントリ名に <code>../../</code> や絶対パスが含まれていると、展開処理が意図したディレクトリの外へ到達することがある。ここで重要なのは、パストラバーサルそのものが常にコード実行を意味するわけではない点となる。 例えばアプリケーションが <code>/opt/app/restore</code> にバックアップを展開する設計だったとして、攻撃者が <code>../../tomcat/webapps/ROOT/shell.jsp</code> というエントリ名を持つZIPを投入できるとする。展開処理が正規化後のパスを検査せず、プロセス権限でその場所に書き込める場合、JSP対応のWebアプリケーションサーバが次のHTTPリクエストでそのファイルを実行する。これが任意ファイル書き込みからRCEへ変わる典型例となる。逆に、書き込み先が実行されない一時ディレクトリに限定され、サービス権限にもWebルートへの書き込み権限がなければ、影響はファイル破壊や設定改ざんにとどまる可能性が高い。 CSIRTの判断では「ZIPをアップロードできるか」だけでなく、「どのプロセス権限で展開されるか」「正規化後のパスが展開先配下に収まるか」「書き込み先が実行可能領域か」を分けて確認したい。検知では、復元APIへのPOST、通常運用外のZIP投入、新規JSPやスクリプトファイルの生成、Webサーバプロセスからの不審な子プロセス起動をつなげて見るとよい。封じ込めでは、該当エンドポイントのネットワーク遮断、ホスト隔離、Web公開ディレクトリの差分取得、投入されたZIPと展開ログの保全を優先する。単にパッチ適用だけで終えると、既に置かれたWeb shellを見落とすため、ファイルシステム調査までを初動範囲に含めたい
