概要

MicrosoftのWebアプリケーション展開ツールWeb Deploy 4.0において、シリアライズデータの処理不備によりリモートから任意コード実行（RCE）が可能となる脆弱性が報告された。攻撃者は細工したリクエストを送信することで、Web Deployサービス（既定ではTCPポート8172）を経由し、サーバ上で任意のコードを実行できる可能性がある。認証前に悪用可能な構成も存在するため、IISやAzure環境での自動デプロイを利用する組織では特に注意が必要である。現時点でMicrosoft公式の修正情報は確認されていないが、PoCの存在が報告されており、KEV登録や実際の攻撃観測に発展するリスクがある。

現場の学び

  • Web Deployは開発・運用の自動化で広く利用されるが、管理者権限で動作する構成が多く、侵害時の影響が大きい。
  • 認証設定やIP制限が不十分な環境では、インターネット経由で直接攻撃されるリスクがある。
  • シリアライズ脆弱性は、コード修正だけでなくプロトコル設計や入力検証の欠陥に起因するため、恒久対策が難しい。

初動・継続対応の示唆

  • Web Deployサービスの外部公開を即時確認し、不要な場合は停止またはファイアウォールで制限する。
  • IISログやWindowsイベントログで異常なmsdeploy.exe呼び出しや不審な接続元を確認する。
  • Microsoftからの正式パッチやアドバイザリを監視し、暫定的に認証必須化・証明書認証を導入する。

Web Deploy

IIS用のWebアプリ展開ツール。自動化に便利だが管理者権限で動作することが多く、露出すると高リスク。

シリアライズ脆弱性

オブジェクトの直列化・復元処理に欠陥があり、任意コード実行を許す問題。入力検証不備と混同されやすい。

RCE（Remote Code Execution）

遠隔から任意のコードを実行される脆弱性。認証前RCEは侵入の初期段階で特に危険。

PoC（Proof of Concept）

脆弱性の実証コード。攻撃者が悪用可能性を検証するために使う。公開度が攻撃拡散の指標となる。
