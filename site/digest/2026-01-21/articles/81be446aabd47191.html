VU#244846: Server-Side Template Injection (SSTI) vulnerability exist in Genshi

Impact判定理由

任意コード実行が可能な設計欠陥であり、Webアプリ経由で悪用されるとサーバ完全侵害に至る。修正未提供で防御困難だが、攻撃成立にはテンプレート入力制御が必要。CERT/CC公表により悪用現実性が高いためHigh評価。

🧾 要約（ChatGPT）

概要

CERT/CCは、Python製テンプレートエンジンGenshiにおけるServer-Side Template Injection (SSTI)脆弱性（VU#244846）を公表した。Genshiはテンプレート式をPythonのeval()やexec()で評価し、変数が未解決の場合にPythonの組み込み名前空間へフォールバックする。この設計により、攻撃者がテンプレート式を制御できる場合、任意コード実行（RCE）が可能となる。現時点で修正版は提供されておらず、テンプレート入力を外部に委ねる構成では深刻なリスクがある。

現場の学び

  • テンプレートエンジンは「文字列整形」ではなくコード実行環境であることを再認識し、入力経路の制御を厳格化する。
  • Python系Webアプリでは、Jinja2やMako等のSSTI防御設定を流用している場合でも、Genshi特有のフォールバック挙動を別途検証する必要がある。
  • 未修正状態が続くOSSコンポーネントは、サンドボックス化やプロセス分離による被害限定を優先検討する。

初動・継続対応の示唆

  • 自組織内でGenshiを利用するWebアプリを棚卸しし、ユーザ入力がテンプレート式に到達する経路を特定・遮断する。
  • アプリケーションログにおいて、${...}やPython組み込み関数呼び出しを含む異常テンプレート評価エラーを監視指標とする。
  • ベンダー修正が出るまで、テンプレート評価を制限するパッチやラッパ実装を暫定的に適用し、外部公開環境では利用停止も検討する。

📌 キーワード解説

Server-Side Template Injection (SSTI)／サーバ側テンプレートインジェクション

テンプレートエンジンがユーザ入力を評価してしまう脆弱性。XSSと異なりサーバ側でコード実行に至る点が特徴。

eval()/exec()

Pythonで文字列をコードとして実行する関数。利便性が高いが、入力制御を誤ると任意コード実行を招く。

RCE（Remote Code Execution）／リモートコード実行

外部から任意コードを実行される脆弱性。権限昇格や横展開の起点となるため最も危険なカテゴリ。

Sandbox／サンドボックス

実行環境を隔離し被害範囲を限定する仕組み。コンテナや仮想化と混同されるが目的は安全な実行制御。
